# Rove companion panel

The Chrome side panel is the primary product surface. The actual website is already alongside it, so Rove should spend its width on the task rather than duplicate a website dashboard.

## Tokens

- Porcelain `#FCFCF9`: quiet base.
- Graphite `#272923`: text and the typographic signature.
- Moss `#536448`: focused actions and active controls.
- Mist `#ECF0E6`: selection and soft surfaces.
- Stone `#73786C`: secondary text.
- Edge `#DFE4D8`: boundaries where they explain a control.

Syne variable, bold, is the statement face for the Rove wordmark, empty invitation and section titles. Commissioner variable is the readable working face for conversation, forms and controls. Fonts and their OFL licenses ship locally. Code retains the platform monospace face.

## Layout

```text
Rove                    History  New  Settings
Current webpage                    Preview

Conversation / compact execution disclosure

Task input
Model name
Thinking             Auto-approve       Send
```

History is an on-demand searchable dialog. Settings replace the conversation and use a compact section switcher. Preview is an optional view selected from the current-page strip, not a permanent pane. The full-tab workbench uses the same interaction structure with a bounded reading column.

## Review before implementation

The initial idea retained the existing narrow dark icon rail. Rejected: it consumed scarce panel width and was a reduced website sidebar. A wide split browser preview was also rejected because Chrome already supplies the page. The font pairing carries the personality; gradients, decorative cards, promotional captions and display-sized dashboard titles do not belong here.

Keep important controls reachable at 320px. Preserve explicit approval, Stop, model selection in chat, complete trace access and keyboard focus. Use motion only for interactive disclosure, and respect reduced motion. Review real extension screenshots at 360/400px and in a full tab before delivery.

Font sources: [Syne](https://github.com/google/fonts/tree/main/ofl/syne), [Commissioner](https://github.com/google/fonts/tree/main/ofl/commissioner).

## Settings and themes

Settings contain Model, Instructions and Tools only. The Model tab is a connection form: endpoint and persistent credential first, a separate full-width model row second, test action next to the connection, and Save anchored at the bottom. Technical tuning is automatic. The composer gives the model name its own row so names and effort labels remain legible at 320px. Menus use shared styled listboxes with keyboard navigation; no native select controls remain.

Light mode retains the porcelain/moss palette. Dark mode uses forest graphite (#242722), a lifted input surface (#2C3029), pale moss (#B8C9A5) and light ink (#E5E8DF). Typography and spatial hierarchy remain identical between themes. The header theme action persists across sessions. Review both themes using the screenshots generated by the real extension UI suite.
## Compact composer revision

The interaction, rather than a modal catalogue, is the visual anchor. Keep the porcelain/forest palette and Syne/Commissioner type. Input starts at one line and grows only as text is entered. All controls share one 28px baseline and padded hit areas: flexible model name, reasoning, approval mode, context ring, send. The model name may ellipsize at narrow widths, with its full name accessible in the trigger and menu. No control wraps to another row.

Model search, reasoning and approvals open anchored menus. The catalogue has a search field, free filter and refresh action, without a decorative heading or custom-ID form. The context ring shows current context occupancy; its adjacent popover separates cumulative chat usage/cost from the latest context and input/output reservations. Unknown usage or prices remain explicitly unknown. Settings replace the header wordmark with an explicit Back to chat action; the chat stays mounted so its draft and position survive.

Review: retaining a two-row control area would repeat the exact spacing problem in the brief. A second floating context footer and a centered catalogue dialog are rejected. Match menu padding to trigger padding and use the ring, not extra captions, as the compact information entry point. Verify 320px through full-tab widths, keyboard dismissal, and persistent follow-up conversations after a worker restart.

## Settings redesign

Settings drop hairline rules for tonal panels (`--panel` behind `--field` inputs), so grouping is carried by tone and spacing. A sliding icon switch replaces the text tabs, matching the workbench view switch. Syne carries section titles and the provider name, which acts as the page's identity. Step limit is a pill stepper; model facts are pills; dictation backends are two selectable tiles; tools are grouped by risk (Look, Act, Dangerous) with a colored dot instead of per-row tags. Save floats on a fade rather than a bordered footer. All rules live in `src/settings.css`, scoped to `.settings-page`.

## App-wide pass

The tonal language from Settings now covers the whole app (`src/chat.css`): pill tab picker and view switch, panel composer with 32px pill controls, rounded popovers lifted by shadow instead of outlines, tonal tables, action ledger and trace rows (colored dot by event kind), history and approval cards. Hairlines are gone everywhere except the step timeline's connector.

Behavior fixes: the Settings model dropdown is replaced by a per-provider "Models in chat" checklist (stored in `chrome.storage.local.visibleModels`; a provider with no entry shows all, and the active model is always listed); the reasoning menu is hidden when a model has no real levels; the approval control reads Auto-approve / Ask first; Inspect page uses its own icon instead of the Trace icon; dead "Connect Chrome" states are removed because the extension is always connected.
